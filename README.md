# FloodWatch — ระบบจัดการข้อมูลน้ำท่วม

เว็บแอปภาษาไทยสำหรับบันทึกและติดตามสถานการณ์น้ำท่วม ใช้ SQLite สำหรับการพัฒนาในเครื่อง และรองรับ PostgreSQL สำหรับการเผยแพร่บนเว็บ

## เริ่มใช้งาน

ต้องมี Python 3.10 ขึ้นไป

```powershell
$env:FLOODWATCH_ADMIN_USERNAME = "flood-admin"
$env:FLOODWATCH_ADMIN_PASSWORD = "<ตั้งรหัสผ่านที่เดายาก>"
python main.py
```

จากนั้นเปิด <http://127.0.0.1:8000> ในเว็บเบราว์เซอร์ ข้อมูลจะถูกเก็บในไฟล์ `flood_data.db` ที่อยู่ในโฟลเดอร์โครงงาน และคงอยู่เมื่อปิด/เปิดแอปใหม่
ผู้เข้าชมดูข้อมูลได้โดยไม่ต้องเข้าสู่ระบบ ส่วนการเพิ่ม แก้ไข และลบต้องเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่านจากตัวแปรข้างต้น ห้ามบันทึกรหัสผ่านไว้ในโค้ดหรือ commit ลง Git

กำหนดพอร์ตหรือไฟล์ฐานข้อมูลเองได้:

```powershell
python main.py --port 8080 --db "D:\Flood_Management\data\flood.db"
```

กด `Ctrl+C` ในหน้าต่างที่ใช้รันเพื่อปิดระบบ

## ความสามารถ

- เพิ่ม แก้ไข และลบรายการสถานการณ์น้ำท่วม
- บันทึกวันที่เกิดเหตุและวันที่รายงาน ประเภทอุทกภัย จังหวัด อำเภอ ตำบล/แขวง และหมู่บ้าน/พื้นที่
- บันทึกระดับน้ำ พิกัด จำนวนครัวเรือน/ประชาชนที่ได้รับผลกระทบ ผู้อพยพ ผู้บาดเจ็บ และผู้เสียชีวิต
- รองรับตัวเลขที่รายงานไม่ได้ โดยจัดเก็บเป็นค่าว่างและแสดง “ไม่ระบุ” ไม่แทนข้อมูลที่ขาดด้วยค่าคาดเดา
- แสดงแผนที่โต้ตอบพร้อมหมุด กดหมุดเพื่อดูรายละเอียดและเปิดแหล่งข้อมูล พิกัดที่กรอกเองจะแทนตำแหน่งโดยประมาณ
- ค้นหาจากจังหวัด อำเภอ ตำบล หมู่บ้าน ประเภทภัย หมายเหตุ และแหล่งข้อมูล พร้อมกรองสถานะและช่วงวันที่
- แสดงภาพรวมรายการ จังหวัด และผลกระทบ โดยยอดที่ไม่มีตัวเลขรายงานจะแสดง “ไม่ระบุ”
- ส่งออกผลการค้นหาและตัวกรองเป็น CSV ภาษาไทย (UTF-8 BOM) โดยป้องกันสูตรอันตรายในสเปรดชีต
- ตรวจสอบข้อมูลก่อนบันทึก และจัดเก็บด้วย SQLite

## API หลัก

- `GET /api/records?q=...&status=...&from=YYYY-MM-DD&to=YYYY-MM-DD` — ค้นหาและกรองรายการ
- `GET /api/summary` — สรุปตัวเลขที่บันทึกทั้งหมด
- `GET /api/export.csv` — ส่งออก CSV โดยรองรับพารามิเตอร์ตัวกรองเดียวกับรายการ
- `GET /api/auth/check` — ตรวจสอบข้อมูลเข้าสู่ระบบผู้ดูแล
- `POST /api/records`, `PUT /api/records/{id}`, `DELETE /api/records/{id}` — เพิ่ม แก้ไข และลบรายการ (ต้องยืนยันตัวตนผู้ดูแล)

เมื่อเริ่มระบบ ฐานข้อมูลเดิมจะถูกปรับ schema เพิ่มเติมโดยเก็บข้อมูลและรหัสรายการเดิมไว้

## ข้อมูลรายงานที่นำเข้า

ฐานข้อมูลตัวอย่างมี 15 รายการจากรายงาน/ประกาศของ ปภ. ที่ตรวจสอบแหล่งอ้างอิงได้ ครอบคลุมเชียงใหม่ พิจิตร เชียงราย และนครราชสีมา ทุกรายการมีลิงก์เอกสารทางการ วันที่รายงาน และบันทึกอธิบายแหล่งที่มา โดยเติมตำบล/หมู่บ้าน สถานะ และจำนวนผู้ได้รับผลกระทบเท่าที่เอกสารระบุได้เท่านั้น ช่องที่รายงานไม่ได้ระบุจะแสดงเป็น “ไม่ระบุ” เช่น ระดับน้ำเป็นตัวเลข พิกัด หรือยอดผู้ประสบภัยในประกาศที่ไม่ได้แจกแจง

ข้อมูลชุดนี้ยังไม่ใช่สถิติครบทุกจังหวัดหรือทุกเหตุการณ์ในช่วงสามเดือน และช่องผลกระทบบางรายการยังไม่มีตัวเลขจากเอกสารต้นทาง จึงเพิ่มเฉพาะข้อมูลที่ยืนยันแหล่งที่มาได้ ไม่สร้างรายการแทนจังหวัดที่ไม่มีรายงาน ยอดสรุปเป็นผลรวมตามวันที่/ขอบเขตของแต่ละรายงาน พื้นที่หรือเหตุการณ์อาจซ้ำกัน และอาจเป็นยอดคงเหลือหรือยอดสะสมตามที่ต้นทางระบุ จึงไม่ควรตีความเป็นยอดรวมปัจจุบันของผู้ประสบภัยที่ไม่ซ้ำกัน

## เผยแพร่บน Render

มีไฟล์ `render.yaml` สำหรับสร้างเว็บแอปบน Render Free และเชื่อมฐานข้อมูล PostgreSQL ของ Neon Free โดยเก็บรหัสผ่านผู้ดูแลและ URL ฐานข้อมูลเป็น secret ระหว่างสร้างบริการ

1. สร้าง PostgreSQL project บน Neon โดยเลือกแผน Free แล้วคัดลอก connection string แบบ pooled จากหน้า **Connect** ของโปรเจกต์ อย่าเผยแพร่ string นี้
2. ใน Render เลือก **New → Blueprint** แล้วใส่ URL repository `https://github.com/nithiphon8542-tech/Flood-Management` เพื่ออ่าน `render.yaml`
3. ระหว่างสร้าง Blueprint ให้กรอก `DATABASE_URL` ด้วย Neon pooled connection string และกำหนด `FLOODWATCH_ADMIN_PASSWORD` เป็นรหัสผ่านที่เดายาก เก็บไว้ใน password manager อย่าส่งค่าทั้งสองในแชตหรือ commit ลง Git
4. หลัง deploy สำเร็จ เปิด URL ที่ Render สร้างให้ ผู้เข้าชมดูข้อมูลได้สาธารณะ ส่วนผู้ดูแลใช้ชื่อ `flood-admin` กับรหัสผ่านที่ตั้งไว้
5. เมื่อเริ่มทำงานครั้งแรก แอปจะนำข้อมูลตั้งต้นจาก `flood_data.db` ไปใส่ใน PostgreSQL เฉพาะเมื่อฐานข้อมูลปลายทางยังว่าง

Render ให้บริการผ่าน HTTPS โดยอัตโนมัติ รหัสผ่านและ URL ฐานข้อมูลถูกเก็บใน Environment Variables ของ Render ไม่อยู่ใน repository หากเปลี่ยนค่าเหล่านี้ให้ restart/redeploy บริการ

ทั้ง Render Free และ Neon Free มีข้อจำกัด: เว็บ Render จะพักเมื่อไม่มีการใช้งานและอาจใช้เวลาสักครู่เพื่อเริ่มตอบสนองอีกครั้ง ส่วน Neon Free อาจพัก compute เมื่อไม่มีการเชื่อมต่อ แม้ข้อมูลจะอยู่ใน PostgreSQL แยกจากไฟล์ชั่วคราวของเว็บ ควรดาวน์โหลด CSV สำรองข้อมูลเป็นระยะ และตรวจสอบโควตาปัจจุบันของผู้ให้บริการ

แอปที่รันในเครื่องจะเปิดรับเฉพาะเครื่องตนเอง (`127.0.0.1`) โดยค่าเริ่มต้น หากไม่มี `DATABASE_URL` จะใช้ SQLite ในไฟล์ `flood_data.db` และหากกำหนด `DATABASE_URL` จะใช้ PostgreSQL

แผนที่ใช้ Leaflet และแผนที่พื้นหลัง OpenStreetMap จึงต้องเชื่อมต่ออินเทอร์เน็ต พิกัดหมุดเป็นตำแหน่งโดยประมาณระดับอำเภอหรือจังหวัด ไม่ใช่พิกัดจุดเกิดเหตุที่ยืนยันแล้ว
